# 博客写作 Agent 规则

当前目录是写作目录。只读取其中的 `1.txt`，它是用户提供的文章思路和素材；不要把 `AGENTS.md` 写入博客。

## 文章

在当前目录创建 Markdown 文件，文件名使用英文小写、数字和连字符。文件开头必须有：

```markdown
---
title: "文章标题"
date: 2026-08-06 12:00:00 +0800
description: "一句话摘要"
tags: [技术, 随笔]
---
```

- `title`、`date`、`description` 必填；首页按 `date` 倒序排列。
- `tags` 选择 1–3 个，不要自造同义或英文标签。可选：
  `技术、编程、软件、硬件、互联网、人工智能、数据、网络安全、开源、产品、设计、创业、商业、职场、管理、教育、学习、阅读、写作、语言、心理、健康、医疗、运动、体育、音乐、电影、游戏、动漫、摄影、旅行、美食、食品、生活、家庭、情感、人物、故事、历史、文化、艺术、社会、政治、经济、金融、投资、法律、环境、科学、未来、随笔、其他`。
- 没有合适标签时用 `其他`。不要添加无用字段或重复标题、日期、摘要。

## 资料补充

将 `1.txt` 中的口语、片段和犹豫式表达整理成明确的观点、论证和结论。不要把“我有个思路”“感觉可行”“可能是”等写作过程原样留在最终文章中。对于未经证实的判断，先查证；仍无法确认时，明确写出前提、条件或待验证事项，不要为了语气确定而编造事实。

用户内容不足时，可以补充背景和事实，但必须查证，不能编造。变化中的数据注明时间；外部事实在文末增加“参考资料”和可靠来源链接。没有可靠来源时不要写成确定事实。

用户材料中的独立方括号是待检索占位符，例如 `[出生人口信息]`。查证后替换它，不要留在成文中。Markdown 链接 `[文字](url)`、图片 `![说明](url)`、代码和 front matter 中的方括号不是占位符。

## 静态资源

资源放在当前目录的 `asset/`，发布时会复制到博客的 `asset/`：

```markdown
![图片](/asset/example.jpg)
[下载文件](/asset/example.zip)
```

支持图片、txt、js、zip 等文件。文件名使用英文、数字、连字符或下划线；引用前确认文件存在。除非用户明确要求，不要自动执行资源中的 JavaScript。

## 发布博客

只有用户明确说“上传博客”“发布文章”“提交到 GitHub”等，才执行发布；单纯写作、修改或润色时不要执行 Git 操作。

目标仓库：

```text
/Volumes/ActiveBackupforBusiness/personal/feiminjian/work/git/minchieh-fay.github.io
```

发布时：

1. 将最终 `.md` 复制到仓库 `blog/`，将引用的资源复制到仓库 `asset/`。
2. 检查 front matter、文件名和资源路径；不要复制草稿、临时文件或本 `AGENTS.md`。
3. 检查仓库已有未提交改动，不要覆盖或回退它们。
4. 在仓库执行：

```bash
git add blog/ asset/
git commit -m "Add new blog article"
git push origin main
```

GitHub Actions 会自动构建发布，不要提交 `dist/`，也不需要手动编译。
