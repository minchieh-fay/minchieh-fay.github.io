# mem0 Memory.search 的混合检索与排序机制

mem0 的 `Memory.search` 在指定用户、Agent 或会话范围内检索相关记忆。它不是单一路径的向量查询：语义召回负责建立候选池，BM25 关键词信号和实体关系信号参与候选排序，之后再按需执行重排。

Python 与 TypeScript SDK 的算法逻辑一致，差异主要在并发实现和结果对象形式。

## 接口边界

调用时必须提供自然语言 `query` 和 `filters`。`filters` 至少包含 `user_id`、`agent_id`、`run_id` 中的一项，避免无范围限制的全库检索；也可以附带元数据条件。

常用参数包括：

- `top_k`：最多返回的结果数，默认 20。
- `threshold`：语义分最低门槛，默认 0.1。它只检查语义分，不检查融合后的综合分。
- `rerank`：是否使用配置好的重排器二次排序，默认关闭。
- `explain`：是否返回分路打分明细。
- `show_expired`：是否包含过期记忆，默认隐藏。
- `reference_date`：仅平台版支持；OSS 版传入时会报错。

结果以 `{"results": [...]}` 返回。单条记忆包含正文、ID、综合分、时间戳和 metadata；开启 `explain` 后可查看各路分数，重排启用且成功时还会有 `rerank_score`。

## 三路检索各自解决什么问题

### 语义召回：找意思相近的记忆

查询文本转换为 embedding 后，向量库按相似度检索。它适用于表达不同但含义接近的查询，例如用“网球”找到“喜欢打网球”的记忆。

语义召回同时决定候选池。系统实际请求的候选数为 `max(top_k * 4, 60)`，而不是只取 `top_k` 条。多取一批是为了在后续过滤过期记忆、融合排序后仍有足够结果。

### BM25：补足精确词项匹配

支持 `keyword_search` 的向量库会额外执行关键词检索，输入是经过词干化的 query。BM25 对专有名词、编号和型号等精确词项有帮助；不支持该能力的向量库则不提供这一路分数。

BM25 原始分数没有固定上界，不能直接与 0 到 1 之间的语义分数相加。因此实现使用 sigmoid 将其归一化到 `[0, 1]`：

```text
normalized = 1 / (1 + e^(-steepness × (rawScore - midpoint)))
```

`midpoint` 和 `steepness` 根据 query 词数调整。词数越多，关键词天然命中的机会越多，归一化所用的 midpoint 也随之提高：

| Query 词数 | Midpoint | Steepness |
|---|---:|---:|
| ≤3 | 5.0 | 0.7 |
| 4–6 | 7.0 | 0.6 |
| 7–9 | 9.0 | 0.5 |
| 10–15 | 10.0 | 0.5 |
| >15 | 12.0 | 0.5 |

### 实体加权：利用实体与记忆的关联

系统从 query 中提取实体，最多保留 8 个去重实体。每个实体分别生成 embedding，并在实体库中检索最多 500 条；相似度达到 `0.5` 的实体会为其关联记忆提供加分。

单个实体对记忆的加分为：

```text
boost = similarity × ENTITY_BOOST_WEIGHT(0.5) × memory_count_weight
memory_count_weight = 1 / (1 + 0.001 × (numLinked - 1)²)
```

关联记忆越多，热度惩罚越强，避免常见实体把大量记忆推到榜单前列。同一条记忆被多个实体命中时只取最高加分，不累加。实体检索出错只记录 warning 并跳过，不中断主检索。

## 融合分数与门槛

候选记忆的融合原始分由语义、BM25 和实体加权组成：

```text
raw = semantic + bm25 + entity_boost
combined = min(raw / max_possible, 1.0)
```

`max_possible` 按本次启用的通道动态取值：只有语义时为 `1.0`；语义加 BM25 时为 `2.0`；语义加实体时为 `1.5`；三路都启用时为 `2.5`。这样不会因为未启用的通道而抬高分母。

`threshold` 在融合之前检查语义分。语义分低于门槛的候选会直接淘汰，不能依靠关键词或实体分数翻案。这个约束让语义相关性保持主信号地位，BM25 和实体只调整候选之间的优先级。

## 一次搜索的处理流程

1. OSS 版本收到 `reference_date` 时直接报错。
2. 拒绝放在函数顶层的实体参数；实体范围应通过 `filters` 传入。
3. 校验 `threshold`、`top_k`，清理 query 首尾空白，并规范化 filters 中的实体 ID；包含空格的 ID 会被拒绝。
4. 检查 filters 是否至少有一个 `user_id`、`agent_id` 或 `run_id`。
5. 将 AND、OR、NOT、比较运算符和通配符等高级过滤条件转换为向量库使用的过滤格式。AND 条件按字段合并，OR 和 NOT 分别转换为 `$or` 和 `$not`；已处理的逻辑键会从传递参数中移除。
6. 生成 BM25 使用的词干化 query，并抽取实体供实体加权使用。
7. 将原始 query 转成向量，执行语义召回，并按 `max(top_k * 4, 60)` 过取候选。
8. 若向量库支持关键词检索，使用词干化 query 执行 BM25 召回并归一化关键词分；否则关键词分为空。
9. 检索实体关联记忆并计算实体加权分。
10. 以语义召回结果作为唯一候选池，根据 `show_expired` 决定是否移除过期记忆。
11. 先按 `threshold` 检查语义分，再计算综合分、降序排列并截取 `top_k`。开启 `explain` 时同时记录各路分数。
12. 将 payload 整理为结果对象，分离正文、hash、时间戳、实体字段和自定义 metadata。
13. 若 `rerank=True`、重排器已配置且结果非空，则调用重排器二次排序。重排失败时保留原排序，不让可选步骤破坏主检索结果。
14. 返回 `{"results": [...]}`。

## 设计边界

候选池只来自语义召回，因此 BM25 或实体命中的条目若未进入语义候选池，就不会单独加入结果。这让检索始终由语义相似度兜底，同时也意味着关键词与实体通道是排序信号，而非独立的候选扩展通道。

实体通道通过热度惩罚控制高频实体的影响；语义门槛则阻止语义无关、仅因词项或实体重合而排名靠前。重排器属于末端可选步骤，失败会降级为原结果。

## Python 与 TypeScript 的实现差异

| 项目 | Python | TypeScript |
|---|---|---|
| 实体加权并发 | `ThreadPoolExecutor`，4 个 worker | `Promise.allSettled` |
| 词干化 | `lemmatize_for_bm25` | 同名工具，基于 `natural` 包 |
| 结果对象 | Pydantic `MemoryItem` | 普通对象与 `MemoryItem` 接口 |

两种 SDK 的算法路径相同；上述差异不改变三路信号的召回与融合规则。
