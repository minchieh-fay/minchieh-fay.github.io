仔细读过 Pi 和 Codex 的 agent loop 后，我对 Agent 的判断又回到了起点：Agent 的核心确实是一个循环。

这个循环可以简称为 BWNC（Break When No Call）：模型返回工具调用就继续，模型不再返回工具调用就退出。

基本流程可以压缩成这样：

1. 把当前上下文送入模型。
2. 如果模型返回工具调用，就执行工具，并把结果追加到上下文。
3. 再次调用模型。
4. 模型不再返回工具调用时，跳出循环。

伪代码大致如下：

```text
while true:
    response = model(messages, system_prompt, tools)
    messages.append(response)

    if response has no tool call:
        break

    results = execute_tools(response.tool_calls)
    messages.append(results)
```

成熟 Agent 的代码当然不只有这几行。Pi 和 Codex 还要处理用户消息预处理，例如用户指定使用某个 skill 或工具；也要处理运行期间的模型切换、人工中断、上下文压缩、权限、异常和多 Agent 通讯。Codex 还维护了用于子 Agent 通讯的 mailbox，以及类似 `worldstate` 的运行状态。

这些机制影响工程可靠性、交互方式和适用范围，却不改变 BWNC 这个基本结构。对于下面的坦克游戏测试，用户消息预处理、运行期间切换模型、mailbox 和其他外围机制都不是决定因素。测试只关心一次任务运行中，模型是否继续调用工具，以及它在系统提示词约束下如何使用工具。

## 同一个循环，结果为什么差很多

我用同一个 30B 模型测试了几个实现，让它们完成“用 HTML 写一个 90 坦克游戏”。结果差异很明显：

- Pi 生成的版本无法正常操控，也没有敌方坦克。
- Codex 生成的版本功能完整，可以实际游玩。
- DeepSeek Harness 生成的版本接近 Pi，基本不可用。

如果只看 loop，这几个系统都遵守同一个 BWNC 机制。差异主要来自模型每一轮收到的系统提示词和可用工具。

### 把 Codex 提示词放进 Pi

随后我取出 Codex 的默认系统提示词（22K），直接放进 Pi 项目的 `AGENTS.md`。这份提示词要求 Agent 持续完成任务，在需要时调用终端命令和补丁工具，并在具备条件时运行验证；同时还规定了响应、计划、权限和异常处理等细节。

这里不需要把整份提示词归纳成几条口号。关键事实是：同一个 BWNC 循环接收了不同的系统提示词。

加入这份提示词后，Pi 生成的坦克游戏已经可以操控和发射子弹。

### 自己实现几十行 Loop

随后我又用脚本自己实现了一个遵守 BWNC 机制的 loop，只用了几十行代码。把同一份系统提示词放进上下文后，生成结果依然不错。

这说明，模型原本并非完全不会写这个游戏。单次运行结果的主导因素显然是系统提示词：它规定模型是否持续工作、是否使用工具，以及是否验证结果。外围机制在这个测试中没有发挥决定性作用。

## 系统提示词决定循环如何运行

BWNC 只规定了循环什么时候继续，系统提示词则决定每次继续时做什么。它会影响模型是否调用工具、如何使用工具、是否运行验证，以及完成任务的标准。

没有合适的系统提示词，模型可能在第一次生成代码后就结束。提示词明确工作方式后，同一个 BWNC 循环才会更可能持续调用工具，把“生成代码”推进到“交付可用结果”。

因此，系统提示词不是装饰性说明，而是 BWNC 循环中的主要行为约束。对于单次任务结果，它的影响远大于那些与本次任务无关的外围机制。

## 复杂代码的价值在哪里

如果 Agent 的核心只是一个 BWNC loop，为什么成熟工具还需要几十万行代码？因为产品难点在循环之外的可靠性和交互。

这些代码通常负责：

- 管理上下文和历史记录，避免上下文超过限制；
- 保存和恢复任务状态；
- 处理中断、超时、异常和重试；
- 限制文件、网络和命令执行权限；
- 管理认证、计费和不同模型；
- 协调子 Agent 与主 Agent 的通讯；
- 提供稳定的终端、编辑器和用户交互体验。

这些代码会影响产品能否稳定运行，但不构成 Agent 的另一种核心控制流。一个几十行的 BWNC loop 足以验证原理，也足以完成这次坦克测试；长期使用时，再补上这些工程能力即可。

## 结论与边界

Agent 的最小核心可以写成一个遵守 BWNC 的“模型调用与工具结果往返”循环。它不神秘，绝大多数人都能用几十行代码实现一个可运行的版本。

“Agent 就是一个 loop”描述的是核心控制流。单次运行结果的主要差异，则来自系统提示词。模型和工具当然也会影响结果，但在这次使用同一个 30B 模型进行的测试里，替换系统提示词已经带来了决定性的变化。

BWNC 可以作为分析 Agent 的最小模型：有工具调用就继续，没有工具调用就退出。Pi、Codex 以及自己写的几十行 loop 都遵守这个模型。差异不在 Agent 是否拥有另一种神秘结构，而在循环收到什么系统提示词，以及模型在这个约束下如何行动。

理解这一点后，分析 Agent 时可以先看 BWNC，再看系统提示词，最后用少量文字交代消息预处理、模型切换、上下文管理和权限等外围机制。它们重要，但与这次坦克游戏测试的结果无关。
